# 🍓 Smart Farm Data Pipeline & AI Forecast System
본 프로젝트는 과거 농가 환경 데이터와 실시간 기상청 예보 데이터를 결합하여, 딸기 비닐하우스 내부의 온습도를 예측하고 최적의 재배 가이드를 제공하는 지능형 데이터 파이프라인 구축 프로젝트입니다.

## 🚀 1주차(2026-05-11~20) 진행상황: 데이터 파이프라인 고도화 및 ML 모델 성능 개선
기존 파이프라인의 수집 및 학습 데이터 스펙을 전면 개편하고 피처 엔지니어링을 적용했습니다. 스마트팜 온실효과의 핵심 도메인 지표인 **`일사량_외부`** 데이터를 발굴하여 피처로 추가했고, 이를 통해 내부 온습도 예측 모델의 정확도를 대폭 끌어올렸습니다.
* **시스템 연동:** Airflow DAG (`strawberry_ai_forecast_final`) 정상 구동 및 PostgreSQL 내 `kma_solar_rad (FLOAT)` 실시간 가상 센서 데이터 적재 완료.
* **데이터셋 스펙 변화:** 기존 6개 변수 기반에서 핵심 피처인 **`일사량_외부`**를 추가하여 총 7개 수집 및 매핑 완료.
* **🌡️ 내부 온도 예측 성능 향상:** - 결정계수 ($R^2$ Score): `0.6177 (61.7%)` ──> **`0.7325 (73.2%)` (+11.48%p 폭등)**
  - 평균 절대 오차 (MAE): **`2.4973 °C` 달성 (오차 범위 0.68 °C 단축)** 🔥
* **💧 내부 습도 예측 성능 변화:**
  - 결정계수 ($R^2$ Score): `0.0855 (8.5%)` ──> **`0.2184 (21.8%)` (+13.29%p 상승)**

## 🚀 2주차(2026-05-21~06-05) 진행상황: 전처리 고도화 및 머신러닝 알고리즘 극한 고도화 (Update! 🌟)
교수님 피드백을 기반으로 데이터 유실 문제를 완벽히 해결하는 Pandas 전처리 파이프라인을 구축했으며, 단순 선형 회귀 모델의 한계를 극복하기 위해 의사결정나무 앙상블 기법(RandomForest)을 도입했습니다. 이에 더해 **도메인 핵심 팩트 피처 융합** 및 **시계열 시차 변수(Lag)**를  도입하여 예측력 상승.

* **교수님 피드백 ① (Pandas 필터링 선행):** 기존에 전체 작물 데이터가 혼재된 상태에서 `dropna()`를 수행하여 딸기 데이터가 유실되던 선후 구조를 전면 개편, **'딸기' 품목을 최우선 필터링**한 후 정제를 시작하도록 로직 수정.
* **교수님 피드백 ② (시계열 선형 보간법 도입):** 데이터 손실을 유발하는 단순 행 삭제 대신 시간 흐름의 연속성을 살리는 **`interpolate(method='linear').ffill().bfill()`** 알고리즘 적용. 학습 데이터 크기가 **5만 건에서 159,187건으로 3배 이상 증가 (데이터 유실률 0%)** 🌟
* **교수님 피드백 ③ (예보 연동 피처 확정):** 미래 기상청 단기예보 API와 연동 불가능한 불필요 피처를 배제하고, 예보 연동성이 뛰어난 **`풍속_외부`**를 최종 독립 변수로 확정 융합.
* **🔥 [도메인 확장] 실제 팩트 기반 환경 변수 추가 발굴 및 융합:**
  - **`누적일사량_외부`**: 단순 순간 일사량이 아닌 아침부터 축적된 누적 열에너지 데이터를 매핑하여 오후 시간대 하우스 내부 온도 예측력 극대화.
  - **`잔존이산화탄소(CO2)`**: 농민의 환기창 개폐 행동에 따라 급변하는 $CO_2$ 농도 특성을 학습시켜, 제어 로그 데이터가 없는 공백을 간접 유추하도록 아키텍처 고도화.
* **⏱️ [시계열 특화] 시계열 관성 피처(Lag Feature) 도입:**
  - 현재 상태를 예측하기 위해 직전 시간(1시간 전)의 타겟 상태를 참고하는 **`상대습도_내부_Lag1`** 변수를 생성 및 주입하여 데이터의 시계열적 관성과 연속성을 모델에 학습시킴.

## 🚀 3주차(2026-06-01~) 진행예정: 도메인 컨텍스트 확장 및 PostgreSQL 관계형 데이터베이스(RDB) 테이블 설계

외부 날씨 기상 변수와 단순 1시간 전 시차 변수만으로는 설명하기 한계가 있었던 내부 습도 예측력($R^2$ 43.4%)을 온도 수준(70~80% 대 이상)으로 끌어올리기 위해, 스마트팜 농가의 물리적·생물학적 환경 데이터 모델링을 위한 백엔드 데이터베이스 인프라 확장 작업을 시작합니다.

### 💡 주요 고도화 및 아키텍처 설계 사항

* **🧪 물리 공식 기반 포차(VPD, Vapor Pressure Deficit) 연산 레이어 설계:**
  - 내부 온도와 습도 데이터를 Tetens 공식 수학 레이어에 통과시켜, 식물이 실제로 느끼는 증산 압력을 대변하는 포차 파생 변수를 실시간 계산하여 모델에 주입.
  - 단순 수치 학습을 넘어 딸기 잎사귀의 호흡(증산 작용 활성화 시점)을 모델이 인지하도록 도메인 지식 최적화.

* **⏱️ 시계열 멀티 시차 변수 확장 계획 (`Lag2`, `Lag3`):**
  - 2주차에 검증된 `Lag1` 성능 폭등 메커니즘을 이어받아, **2시간 전 및 3시간 전 내부 습도의 누적 변화 흐름(Trend)**을 파악할 수 있는 시계열 확장 레이어 기획.

* **🗄️ 인프라 정합성을 반영한 PostgreSQL 신규 테이블 구조 정의 (DDL 설계):**
  - 실제 도커 컴포즈 인프라 설정값(계정: `tae_tae`, 데이터베이스명: `agriculture`)을 정조준한 백엔드 테이블 설계.
  - **`farm_crop_context` (생육 및 정식일 테이블):** 작물 품목(`딸기`), 땅에 심은 날짜(`정식일`), 현재 생육 단계(`정식기/개화기/수확기`)를 관리하여 작물의 나이와 크기(DAT)에 따른 수분 예측 기반 마련.
  - **`sun_time_context` (일출몰 시간 테이블):** 순천 지역의 날짜별 정확한 `일출 시간` 및 `일몰 시간` 데이터를 조인하여, 낮과 밤의 전환기(창문 제어 타이밍)에 발생하는 급격한 습도 변동성을 제어.

* **🔗 데이터 파이프라인 조인(Join) 아키텍처 구상:**
  - Airflow가 데이터를 정제할 때, 도커 내부의 `agriculture` 데이터베이스에서 오늘 날짜 기준의 생육 단계와 일출몰 데이터를 `SELECT`하여 머신러닝 독립 변수(X) 레이어에 동적으로 융합(Join)하는 데이터 흐름 기획 중.
